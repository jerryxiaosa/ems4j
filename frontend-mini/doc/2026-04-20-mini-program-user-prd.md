# EMS4J 用户端微信小程序 PRD

- 文档版本：V1.0
- 创建日期：2026-04-20
- 文档状态：需求确认版
- 适用范围：`frontend-mini` 第一阶段用户端小程序

## 1. 概述

本项目拟建设一个面向终端用户的微信小程序。用户可通过微信手机号快捷登录，在小程序中查看自己唯一账户下的用能、费用、余额、订单，并完成充值支付。

第一阶段聚焦“用户自助查看与支付闭环”，暂不覆盖管理端、消息通知、复杂运营能力和机构绑定能力。小程序将作为独立前端工程建设，后续可整体迁移出 `ems4j` 仓库，且不得依赖 `frontend-web` 源码。

## 2. 问题定义

当前系统以后台管理端为主，用户缺少移动端自助入口，主要问题包括：

- 用户无法在微信端便捷查看自己的账户用能、费用和余额情况。
- 用户无法在微信端直接完成充值和支付。
- 后台已建立账户关系，但用户端没有与手机号直接对应的统一入口。
- 当用户未开户或账户状态异常时，缺少统一、清晰的引导触达页面。

## 3. 产品目标

第一阶段目标如下：

- 为已开户用户提供一个微信端可直接访问的用户入口。
- 让用户可以查看近七日电量、电费趋势，以及当前余额。
- 让用户可以查看账单月汇总与月内按日明细。
- 让用户可以查看账户下的电表列表与单表详情。
- 让用户可以完成充值下单和微信支付。
- 让用户可以查看充值订单及支付状态。

## 4. 目标用户

### 4.1 主要用户

- 已在后台存在账户信息的终端用户
- 通过手机号与唯一账户绑定的用户
- 需要查看个人机构下账户数据并完成充值支付的用户

### 4.2 用户约束

- 一个手机号只对应一个账户
- 用户端只能看到自己唯一账户下的数据
- 不支持在小程序内自行绑定机构

## 5. 范围定义

### 5.1 第一阶段范围内

- 微信手机号快捷登录
- 引导页
- 首页
- 充值页
- 微信支付
- 支付结果页
- 订单页
- 账单月列表页
- 账单日明细页
- 电表列表页
- 单表详情页
- 我的页

### 5.2 第一阶段范围外

- 微信通知/订阅消息
- 失败原因、关闭原因等复杂订单详情
- 当月月汇总
- 自定义日期范围筛选
- 独立账户详情页
- 活动、公告、营销能力

## 6. 核心业务规则

### 6.1 登录与账户识别

- 用户使用微信手机号快捷登录。
- 后端按手机号匹配账户。
- 一个手机号只能匹配一个账户。
- 若手机号未匹配到账户、未开户或账户状态异常，登录后进入引导页。

### 6.2 首页口径

- 首页展示当前余额。
- 若账户为按需模式且账户下存在多块表，余额展示为多表余额合计。
- 首页展示一张趋势图，支持“电费 / 电量”切换。
- 首页图表默认展示电费。
- 图表展示口径为近七日数据。

### 6.3 充值口径

- 支持固定档位和自定义金额。
- 非按需模式：直接按账户充值。
- 按需模式：用户需先选择具体电表，再进行充值。

### 6.4 账单口径

- 账单分两级：
  - 一级：按月汇总列表
  - 二级：月内按日明细
- 一级列表中需要展示“本月”入口。
- 历史月份可查看月汇总与该月按日明细。
- 本月不展示月汇总，只允许查看已过去日期的数据。
- 月初若当月暂无可展示数据，需要展示明确提示信息。

### 6.5 单表详情口径

- 单表详情展示单表基础信息、余额、尖峰平谷深谷电量以及总电量。
- 第一阶段不展示单表电费。

### 6.6 支付结果页口径

- 支付结果页仅展示支付成功或失败状态。
- 提供“返回首页”“查看订单”两个操作入口。
- 第一阶段不在支付结果页主动刷新余额。

## 8. 页面需求

### 8.1 登录页

**目标**

- 完成微信手机号快捷登录。

**核心功能**

- 发起微信授权登录
- 获取手机号
- 调用后端登录接口

**页面结果分流**

- 账户正常：进入首页
- 未匹配账户 / 未开户 / 账户状态异常：进入引导页

### 8.2 引导页

**目标**

- 承接无法进入正常业务首页的用户。

**核心功能**

- 展示当前无法正常使用的原因
- 提示联系管理员或机构处理

**第一阶段说明**

- 不提供在线申诉、在线开户、消息通知等扩展操作

### 8.3 首页

**目标**

- 用能优先展示账户当前情况

**核心功能**

- 展示当前余额
- 若账户为按需模式且存在多块表，展示多表余额合计
- 展示近七日电费/电量趋势图
- 默认展示电费趋势
- 支持切换查看电量趋势
- 提供“去充值”按钮
- 在机构名称旁展示“共 X 个电表 >”入口，点击进入电表列表页

### 8.4 充值页

**目标**

- 完成充值下单前的确认与金额选择

**核心功能**

- 展示当前充值对象
  - 非按需模式：账户
  - 按需模式：电表
- 支持固定金额档位选择
- 支持自定义金额输入
- 按需模式通过下拉框选择具体电表
- 提交后进入支付流程

### 8.5 支付结果页

**目标**

- 告知用户支付状态，并引导后续操作

**核心功能**

- 展示支付成功/失败
- 返回首页
- 查看订单

### 8.6 订单页

**目标**

- 查看充值订单和当前支付状态

**核心功能**

- 展示充值订单列表
- 展示支付状态
- 支持分页浏览订单列表

**第一阶段不做**

- 失败原因详情
- 关闭原因详情
- 复杂订单详情页

### 8.7 账单月列表页

**目标**

- 展示月份维度的账单入口

**核心功能**

- 展示历史月份汇总
- 展示“本月”入口
- 点击月份进入月内按日明细页

### 8.8 账单日明细页

**目标**

- 查看指定月份下的每日数据

**核心功能**

- 展示某月按日数据列表
- 本月仅展示已过去日期
- 月初如暂无数据则展示提示信息
- 每日明细展示尖峰平谷深谷电量、总电量、尖峰平谷深谷电费与总电费

### 8.9 电表列表页

**目标**

- 展示账户下全部电表并支持进入单表详情

**核心功能**

- 展示电表列表
- 展示电表余额与当前状态
- 跳转到单表详情页

### 8.10 单表详情页

**目标**

- 查看单表的余额与用电信息

**核心功能**

- 展示单表基础信息
- 展示单表余额
- 展示尖峰平谷深谷电量
- 展示总电量

**第一阶段不做**

- 单表电费展示

### 8.11 我的页

**目标**

- 展示用户基础信息，并承接订单入口与退出登录操作

**核心功能**

- 展示手机号
- 展示所属机构基础信息
- 展示当前账户状态
- 提供“我的订单”入口，跳转到订单页
- 提供退出登录入口

## 9. 用户故事

### 9.1 登录

作为一个已有账户的用户，  
我希望通过微信手机号直接登录，  
以便快速进入自己的账户页面。

验收标准：

- 用户可通过微信手机号快捷登录
- 后端按手机号识别唯一账户
- 登录成功后进入首页或引导页

### 9.2 首页查看用能

作为一个用户，  
我希望在首页快速看到近七日电费、电量和当前余额，  
以便了解最近的用能和费用情况。

验收标准：

- 首页展示当前余额
- 首页图表支持“电费/电量”切换
- 图表默认展示电费
- 图表口径为近七日

### 9.3 查看账单

作为一个用户，  
我希望先看月汇总，再进入某个月查看每日数据，  
以便逐层查看账单而不是一次看到太多信息。

验收标准：

- 账单一级页面展示月份列表
- 本月在一级页面中可见
- 点击月份后可查看该月按日数据
- 本月不展示月汇总，只展示已过去日期

### 9.4 充值支付

作为一个用户，  
我希望在小程序里直接充值并完成微信支付，  
以便快速补足账户或电表余额。

验收标准：

- 支持固定金额与自定义金额
- 非按需模式按账户充值
- 按需模式可先选电表再充值
- 可发起微信支付

### 9.5 查看订单

作为一个用户，  
我希望查看充值订单及支付状态，  
以便确认支付是否完成。

验收标准：

- 可查看充值订单列表
- 每条订单展示支付状态
- 可通过“我的订单”进入订单页
- 支付结果页可跳转到订单页

### 9.6 查看电表

作为一个用户，  
我希望查看账户下的电表列表和单表详情，  
以便了解每块表的余额和用电情况。

验收标准：

- 可查看电表列表
- 可进入单表详情
- 单表详情展示余额与电量

## 10. 交互与体验要求

- 首页信息结构优先级：余额 > 趋势图 > 关键操作入口
- 图表只保留一张，减少首屏复杂度
- 账单采用两级结构，避免首屏堆积过多数据
- 对“未开户 / 未匹配账户 / 账户异常”用户，统一进入引导页，避免出现空白业务页
- 支付结果页保持轻量，避免把余额刷新逻辑放入第一阶段

## 11. 成功指标（第一阶段建议）

以下指标作为第一阶段建议指标，具体数值在项目立项后再确认：

- 登录成功率
- 首页访问率
- 充值发起率
- 支付成功率
- 订单查询使用率
- 账单页访问率

## 12. 技术与工程约束

- 小程序工程目录位于 `frontend-mini/`
- 小程序相关文档统一写入 `frontend-mini/doc/`
- 小程序工程必须保持独立性，未来可整体迁移到独立版本库
- `frontend-mini` 不得依赖 `frontend-web` 源码
- 小程序与后端的边界统一为 HTTP API
- 第一阶段仅编写 PRD，不在本文展开具体技术实现方案

## 13. 风险与注意事项

- 手机号与账户的唯一映射必须在后端保持稳定，否则会影响登录体验
- 充值目标在按需模式下可能是电表而非账户，充值页必须清楚表达对象
- 本月账单无月汇总，容易让用户误解为“没有数据”，需要明确提示文案
- 未开户或异常账户用户虽然可登录，但不能误导其进入业务首页

## 14. 依赖与前置条件

- 后端具备手机号识别账户能力
- 后端具备用户端专用查询接口
- 后端具备微信小程序支付能力
- 后端可按账户模式正确识别充值落点
- 后端可提供月汇总与日明细数据

## 15. 待确认项

- 引导页的具体提示文案
- 近七日图表的默认样式与交互细节
- 账单页月汇总和日明细的具体字段口径
- 订单页是否需要增加订单金额字段的突出展示
