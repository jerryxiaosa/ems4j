- 文档版本：V1.0

- 对照文档：
  - `2026-04-20-mini-program-user-prd.md`

## 1. 对照结论

当前两份文档已经完成主要页面结构与核心业务规则的对齐，可作为下一阶段技术方案输入。

本轮对照后的结论如下：

- 已对齐：页面结构、核心流程、首页入口、充值分支、确认支付页、账单两级结构、电表相关页面、订单入口位置
- 待细化：提示文案、图表交互细节、部分字段展示强调方式
- 可进入下一阶段：接口口径梳理、技术方案、开发计划

## 2. 全局结构对照

| 对照项 | PRD | 高保真原型 | 结论 |
|---|---|---|---|
| 产品定位 | 用户端微信小程序，只服务唯一账户用户 | 启动后只存在“首页 / 引导页”两种主入口 | 已对齐 |
| 登录方式 | 微信手机号快捷登录 | 登录页仅保留微信手机号快捷登录按钮 | 已对齐 |
| 异常登录去向 | 未匹配 / 未开户 / 账户异常进入引导页 | 登录流程原型与引导页状态一致 | 已对齐 |
| Tab 结构 | 首页 / 充值 / 账单 / 我的 | 首页 / 充值 / 账单 / 我的 | 已对齐 |
| 非 Tab 页面 | 订单、电表、账单二级页、确认支付页、支付结果页 | 页面结构与流程原型一致 | 已对齐 |
| 前端独立性 | `frontend-mini` 独立，不依赖 `frontend-web` | 原型文档未引入后台前端依赖 | 已对齐 |

## 3. 核心业务规则对照

| 业务规则 | PRD | 高保真原型 | 结论 |
|---|---|---|---|

| 首页展示余额 | `6.2 首页口径` | 首页顶部展示当前余额 | 已对齐 |
| 按需模式余额口径 | 多表余额合计 | 首页明确写出“按需模式时展示：多表余额合计” | 已对齐 |
| 首页图表口径 | 一张图，电量/电费切换，默认电量，近七日 | 首页原型一致 | 已对齐 |
| 非按需充值 | 充值到账户 | 充值页（非按需模式）一致 | 已对齐 |
| 按需充值 | 先选电表再充值 | 充值页（按需模式）用下拉框选电表 | 已对齐 |

| 单表详情口径 | 展示在线状态、余额、尖峰平谷深谷电量、总电量，不展示电费 | 单表详情页原型一致 | 已对齐 |
