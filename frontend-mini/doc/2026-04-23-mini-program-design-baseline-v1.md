# EMS4J 用户端微信小程序轻量设计基线（V1）

- 文档版本：V1.0
- 创建日期：2026-04-23
- 对应风格：`2026-04-23-mini-program-ui-style-samples.html` 方案 C
- 用途：作为第一轮高保真原型的统一视觉依据

## 1. 设计目标

本次设计基线服务于第一阶段用户端微信小程序高保真原型，目标是：

- 保持**生活服务感**
- 同时强调**账单、余额、支付**场景的可信度
- 页面层次清晰，适合小程序高频查看
- 不做过度品牌化，不追求强视觉噪音

整体气质定义为：

**轻账单感、偏生活服务、克制但不生硬。**

## 2. 视觉关键词

本轮高保真原型统一围绕以下关键词展开：

- 清爽
- 可信
- 柔和
- 数据清晰
- 轻服务感

避免的方向：

- 过暖、过生活化，导致账务可信感下降
- 过冷、过后台化，导致用户端体验发硬
- 重阴影、重描边、重渐变堆叠

## 3. 色彩基线

### 3.1 主色与辅助色

- 主色：`#2563EB`
- 辅助色：`#14B8A6`

使用原则：

- 主色承担主按钮、激活状态、图表主线
- 辅助色用于图表渐变、在线状态、轻强调信息

### 3.2 中性色

- 页面背景：`#EDF3F8`
- 浅背景渐变起点：`#F7FAFC`
- 主文字：`#152234`
- 次级文字：`#6A7A8F`
- 分割线 / 弱边框：`rgba(79, 123, 167, 0.08 ~ 0.12)`

### 3.3 状态色

- 成功 / 在线：`#14B86A`
- 警示：`#F59E0B`
- 失败：`#EF4444`

说明：

- 第一阶段在线状态可优先使用“蓝绿系”或标准绿色表达
- 不建议出现太多红黄橙提示块，除非页面明确有异常语义

## 4. 字体与层级

### 4.1 字体策略

小程序界面使用系统默认中文字体栈，不额外追求品牌字体。

推荐字体栈：

```text
SF Pro Display / PingFang SC / Hiragino Sans GB / Microsoft YaHei / sans-serif
```

数字区域优先强调对齐和清晰：

- 金额、余额、关键统计值使用更紧凑的数字风格
- 不额外引入花哨数字字体

### 4.2 字号层级

建议统一使用以下层级：

- 页面标题：`18px / 700`
- 卡片标题：`16px / 700`
- 主数值（余额）：`32px ~ 36px / 700`
- 普通正文：`14px / 400~500`
- 次级说明：`12px / 500`
- Tab 文案：`11px ~ 12px / 500~700`

### 4.3 数字展示原则

重点数字包括：

- 当前余额
- 应付金额
- 总电量 / 总电费

要求：

- 统一右侧或基线对齐
- 避免过多装饰性单位
- `¥` 可缩小一级，主数值本体更突出

## 5. 间距与布局

### 5.1 页面级间距

- 页面左右边距：`16px ~ 18px`
- 模块纵向间距：`12px ~ 16px`
- 页面顶部首块与导航间距：`16px ~ 20px`

### 5.2 卡片内部间距

- 卡片内边距：`16px ~ 18px`
- 卡片内模块间距：`10px ~ 14px`

### 5.3 布局原则

- 首页采用“上重下轻”的布局：
  - 顶部账户卡片
  - 中部图表卡片
  - 底部依赖 Tab 继续分流
- 充值页强调单列流程，不做多栏
- 我的页强调列表和入口，不做复杂信息栅格

## 6. 圆角、阴影、边框

### 6.1 圆角

- 页面主卡片：`20px ~ 24px`
- 输入框 / 选择框：`16px`
- 按钮：`16px`
- 胶囊标签：`999px`

### 6.2 阴影

统一使用轻阴影：

```text
0 14px 30px rgba(12, 43, 71, 0.08)
```

原则：

- 阴影只做层次，不做戏剧效果
- 同一页面最多 2 种阴影强度

### 6.3 边框

- 弱边框优先
- 不使用重描边
- 卡片边框建议在浅背景下保持 `8% ~ 12%` 透明度

## 7. 组件基线

### 7.1 顶部账户卡片

首页顶部卡片承载：

- 账户名称
- `共 X 个电表 >`
- 当前余额
- 补充说明
- `去充值`

设计要求：

- 卡片必须是首页最强视觉焦点
- 余额数字是卡片的第一重点
- `去充值` 是卡片内主操作按钮
- 电表入口做成轻胶囊，不做重按钮

### 7.2 按钮

主按钮：

- 背景：主色到辅助色轻渐变
- 文字白色
- 高度：`40px ~ 44px`
- 圆角：`16px`

次按钮：

- 白底 / 浅底
- 边框弱化
- 颜色使用主色系文字

### 7.3 输入框 / 下拉框

用于充值页：

- 背景白色或近白色
- 边框很轻
- 高度约 `48px`
- 不做复杂图标装饰

### 7.4 Tab 栏

Tab 风格要求：

- 浅背景
- 激活项使用主色或主色渐变
- 图标简洁、圆角方块感
- 不做过度拟物

### 7.5 列表入口

用于“我的订单”“退出登录”等：

- 卡片式列表项
- 左标题、右说明 / 箭头
- 间距宽松
- 点击区域清晰

## 8. 图表基线

首页只保留一张图表，支持：

- 电费
- 电量

切换显示。

### 8.1 图表类型

推荐：

- 折线图 + 轻面积填充

不建议：

- 柱状图
- 过重网格线
- 多图叠加

### 8.2 图表风格

- 电费 / 电量都使用同一套图表容器
- 颜色从主色渐变到辅助色
- 节点点位保留，但数量不要太强
- X 轴仅展示少量关键日期

### 8.3 图表容器

- 圆角：`20px`
- 背景：略高于页面背景的浅色面板
- 内边距：`12px ~ 14px`

## 9. 页面级风格要求

### 9.1 首页

- 重点是“余额 + 趋势图”
- 不堆太多入口
- 页面要看起来像“我的用能首页”，不是后台仪表盘

### 9.2 充值页

- 流程感比装饰性更重要
- 输入金额、确认金额、支付按钮要明显分层
- 不要做得像复杂金融产品

### 9.3 账单页

- 强调清晰、规整
- 以数据可读性优先
- 不在账单页增加不必要的装饰元素

### 9.4 我的页

- 轻量、干净
- 更像服务入口页
- 不要堆后台信息

## 10. 第一轮高保真输出范围

基于这份基线，第一轮高保真建议优先输出：

1. 首页
2. 充值页（非按需）
3. 充值页（按需）
4. 账单月列表页
5. 我的页

第二轮再补：

1. 登录页
2. 引导页
3. 订单页
4. 电表列表页
5. 单表详情页
6. 支付结果页

## 11. 当前不在本轮定死的内容

本轮不强行定死：

- 全量图标库
- 动效规范
- 暗色模式
- 全量组件库规范
- 完整切图规范

原因：

- 当前目标是先完成高保真原型评审
- 不做过重设计系统

## 12. 一句话结论

本轮高保真统一采用：

**方案 C 的整体视觉方向：蓝青双色、轻账单感、强调数据可信，同时保留生活服务小程序的轻盈感。**
